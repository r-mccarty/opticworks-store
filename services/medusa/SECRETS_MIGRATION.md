# Medusa Backend Secrets - Infisical Migration Guide

**Created**: 2025-11-19
**Purpose**: Safely migrate backend secrets from Ansible to Infisical without breaking production

---

## Overview

This guide helps you migrate Medusa backend secret management from **Ansible-only** to **Infisical-powered**, while preserving your current working deployment.

### Current State (Before Migration)
- ✅ Backend deployed on Hetzner via Ansible
- ✅ Health checks passing
- ✅ Admin account configured and working
- ✅ Secrets stored in `infrastructure/ansible/group_vars/secrets.yml`
- ✅ `.env` file generated by Ansible template during provisioning

### Target State (After Migration)
- ✅ Current working secrets preserved in Infisical
- ✅ Can pull secrets via `pnpm run medusa:secrets:pull`
- ✅ Team access to backend secrets via Infisical
- ✅ Ansible still works (uses Infisical as source of truth)
- ✅ No production downtime

## Migration Steps (Safe, Non-Destructive)

### Step 1: Push Current Working Secrets to Infisical

This preserves your current working configuration in Infisical.

```bash
# From repo root
pnpm run medusa:secrets:push

# Or directly:
cd services/medusa
pnpm run secrets:push
```

**What it does**:
1. Reads `infrastructure/ansible/group_vars/secrets.yml`
2. Extracts all backend secrets (DB password, JWT, cookies, admin creds)
3. Constructs DATABASE_URL with proper encoding
4. Shows you a preview of what will be pushed
5. Asks for confirmation before pushing
6. Pushes to Infisical path: `/medusa` (production environment)

**Expected output**:
```
=== Push Medusa Backend Secrets to Infisical ===

📋 Extracting secrets from Ansible secrets.yml...

✅ Extracted secrets from Ansible
Preview of secrets to push:
  - DATABASE_URL (with password)
  - REDIS_URL
  - MEDUSA_ADMIN_EMAIL: admin@optic.works
  - MEDUSA_ADMIN_PASSWORD: [encrypted]
  - JWT_SECRET: 310290041d7bef61... (64 chars)
  - COOKIE_SECRET: febbd9baba4d6b93... (64 chars)
  - CLOUDFLARE_TUNNEL_ID: db4738a9-20b7-4dd7-bde2-0760e0188071

Push these secrets to Infisical /medusa path? (yes/no): yes

📤 Pushing to Infisical...

✅ SUCCESS! Backend secrets pushed to Infisical
Location: OpticWorks → production → /medusa

Current working state preserved in Infisical ✅
```

### Step 3: Test Pull Locally (Safe - Won't Affect Production)

Pull secrets to a local test file to verify the pull mechanism works:

```bash
# From repo root
pnpm run medusa:secrets:pull

# Or directly:
cd services/medusa
pnpm run secrets:pull
```

**What it does**:
1. Creates backup of existing `.env` if present: `.env-backups/.env.backup.YYYYMMDD_HHMMSS`
2. Pulls secrets from Infisical `/medusa` path
3. Writes to `services/medusa/.env`
4. Validates critical secrets are present
5. Shows summary of pulled variables

**Expected output**:
```
=== Pull Medusa Backend Secrets from Infisical ===

📦 Backing up existing .env...
✅ Backup saved: .env-backups/.env.backup.20251119_150000

📥 Pulling secrets from Infisical...
Path: /medusa
Environment: production

✅ SUCCESS! Secrets pulled from Infisical

📊 Summary:
  - Variables pulled: 11
  - Saved to: /workspaces/solar-saas-template/services/medusa/.env
  - Backup: .env-backups/.env.backup.20251119_150000

🔍 Validating critical secrets...
✅ All critical secrets present

Next steps:
  1. Review the pulled secrets: cat services/medusa/.env
  2. If on Hetzner, restart Medusa: pm2 restart medusa-prod
  3. Verify health: curl https://api.optic.works/health
```

### Step 4: Compare Pulled .env with Current State

Before deploying to production, verify the pulled secrets match what's currently working:

```bash
# If you have SSH access to Hetzner node
ssh hetzner-node

# Compare current production .env with Ansible template
cat /opt/opticworks/medusa-backend/services/medusa/.env

# Check these critical values match Ansible:
# - DATABASE_URL (especially password encoding)
# - JWT_SECRET
# - COOKIE_SECRET
# - MEDUSA_ADMIN_PASSWORD
```

**Key things to verify**:
- [ ] DATABASE_URL password is URL-encoded (e.g., `%2F` for `/`)
- [ ] JWT_SECRET is 64 characters
- [ ] COOKIE_SECRET is 64 characters
- [ ] MEDUSA_ADMIN_EMAIL matches
- [ ] CORS values match

### Step 5: Update Hetzner Node (Optional - Can Defer)

**ONLY DO THIS IF** you want to switch Hetzner to pull from Infisical instead of Ansible.

**Current Ansible approach still works** - Ansible reads from `secrets.yml`, which can be synced from Infisical.

#### Option A: Keep Using Ansible (Recommended)

Update Ansible to pull from Infisical as source of truth:

```bash
# Use existing script to sync Ansible from Infisical
cd infrastructure/ansible
bash scripts/generate-secrets-from-infisical.sh

# Then provision as normal
ansible-playbook playbooks/medusa-provision.yml
```

#### Option B: Direct Infisical Pull on Hetzner (Advanced)

SSH to Hetzner and pull directly:

```bash
ssh hetzner-node
cd /opt/opticworks/medusa-backend/services/medusa

# Install Infisical CLI if not present
curl -1sLf 'https://dl.cloudsmith.io/public/infisical/infisical-cli/setup.deb.sh' | sudo -E bash
sudo apt-get update && sudo apt-get install -y infisical

# Set service token as environment variable (from GitHub secrets or Infisical)
export INFISICAL_SERVICE_TOKEN=st.xxxxx

# Pull secrets
infisical export --env=production --path=/medusa --format=dotenv > .env.new

# Compare with current
diff .env .env.new

# If looks good, replace
mv .env .env.backup.$(date +%Y%m%d)
mv .env.new .env

# Restart Medusa
pm2 restart medusa-prod

# Verify health
curl http://localhost:9000/health
curl https://api.optic.works/health
```

## Rollback Procedure

If anything goes wrong, you can easily rollback:

### If Pull Failed Locally
The script auto-restores from backup. But if needed:

```bash
cd services/medusa
ls -la .env-backups/
# Find latest backup
cp .env-backups/.env.backup.YYYYMMDD_HHMMSS .env
```

### If Production is Broken
Ansible state is still intact:

```bash
# Re-provision from Ansible (uses secrets.yml)
cd infrastructure/ansible
ansible-playbook playbooks/medusa-provision.yml
```

Or manually restore on Hetzner:

```bash
ssh hetzner-node
cd /opt/opticworks/medusa-backend/services/medusa
ls -la .env.backup.*
cp .env.backup.YYYYMMDD .env
pm2 restart medusa-prod
```

## Common Issues

### Issue: Push script can't find Ansible secrets.yml

**Error**:
```
❌ Ansible secrets.yml not found: ../../infrastructure/ansible/group_vars/secrets.yml
```

**Fix**:
```bash
# Make sure you're in the right directory
cd services/medusa
pwd  # Should show .../solar-saas-template/services/medusa

# Check if secrets.yml exists
ls -la ../../infrastructure/ansible/group_vars/secrets.yml
```

---

### Issue: INFISICAL_SERVICE_TOKEN not set

**Error**:
```
❌ INFISICAL_SERVICE_TOKEN not set
```

**Fix**:
```bash
# Check if token is in environment
echo $INFISICAL_SERVICE_TOKEN

# If empty, check GitHub Codespaces secrets
# Or get token from Infisical web UI
```

---

### Issue: Pull script shows missing critical secrets

**Error**:
```
⚠️  WARNING: Missing critical secrets:
  - DATABASE_URL
  - JWT_SECRET
```

**Fix**:
This means push didn't work correctly. Check:

1. Did Step 1 (push) succeed?
2. Are secrets visible in Infisical web UI?
3. Are you pulling from correct path (`/medusa`)?
